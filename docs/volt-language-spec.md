# Volt Programming Language Specification v1.0

## 0. Design Decisions & Assumptions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Comment syntax | `//` (line comments only in v1) | `//` is the standard in compiled systems languages (C/C++/Rust); unambiguous with division operator due to lexer context. Block comments (`/* */`) deferred to v2 for simplicity. |
| Function keyword | `func` | Explicitly listed in the language goals keyword list; distinguishes Volt from Python. |
| String type | Immutable, UTF-8 encoded | Matches C string null-terminated representation for easy interop. |
| Semicolons | Optional at end of statement lines | Single statements per line use newline as terminator. Semicolons used only to separate multiple statements on one line. |
| Indentation | 4 spaces (not tabs) | Python convention, avoids tab/space mixing bugs. Mixed indentation is a compile error. |
| Entry point | Implicit `main()` | The top-level code in a `.volt` file that is compiled is the entry point. No explicit `main()` function needed. Equivalent to the global scope running at startup (maps to Arduino `loop()`/`setup()`). |

## 1. Keywords

Reserved words (cannot be used as identifiers):

```
func      var       if        elif      else      while     for
return    import    in        break     continue  true      false
null      module    const     not       or        and
```

Reserved for future use (v2+): `class`, `enum`, `match`, `try`, `except`, `async`, `await`, `yield`, `export`, `as`, `from`.

## 2. Type System

Volt is **statically typed** with optional type annotations. The compiler infers types where annotations are omitted.

### 2.1 Primitive Types

| Type | Description | C equivalent | Example |
|------|-------------|-------------|---------|
| `int` | 16-bit signed integer (AVR native) | `int16_t` | `var x int = 42` |
| `float` | 32-bit IEEE 754 float | `float` | `var pi float = 3.14` |
| `bool` | Boolean true/false | `bool` (stdbool.h) | `var flag bool = true` |
| `string` | Immutable character sequence | `const char*` | `var msg = "hello"` |

### 2.2 Array Types

```
var nums int[] = [1, 2, 3]       // type-annotated
var items = [1.0, 2.0, 3.0]      // inferred as float[]
var empty int[10]                  // fixed-size array (uninitialized)
```

Arrays are **fixed-size at declaration**. Dynamic resizing is not in v1 scope. Array index access: `nums[0]`.

### 2.3 Module Types (Hardware Handles)

Each built-in hardware module defines a **nominal type** matching the module name. These are not user-declarable structs — they are opaque handles generated by the compiler.

```
var s Servo = Servo.Init(5)       // s has type Servo (inferred)
var b = Arduino.Init()            // b has type Arduino
```

Module types are **first-class values**: they can be assigned, passed to functions, and returned from functions.

### 2.4 Type Conversion

No implicit narrowing conversions. Explicit conversions:

```
var a int = 5
var b float = float(a)            // explicit cast: 5.0
```

Supported casts: `int()`, `float()`, `bool()`. Pointer/reference casts are not exposed to the user.

### 2.5 Literals

```
42              // int
3.14            // float
true, false     // bool
"hello"         // string
null            // null value (uninitialized handle sentinel)
[1, 2, 3]       // array literal
```

## 3. Comment Syntax

```
// This is a comment. Everything from // to end of line is ignored.
var x = 5    // inline comment
```

Block comments (`/* ... */`) are **not supported** in v1. The `//` token is checked during lexing — the characters `/` followed immediately by `/` (no whitespace) in non-string context begin a comment. Standalone `/` is the division operator.

## 4. Full Grammar (EBNF)

```
// ── Top Level ──────────────────────────────────────────

program           = { top_level_stmt } ;

top_level_stmt    = function_def
                  | module_decl
                  | import_stmt
                  | statement
                  ;

// ── Module System ──────────────────────────────────────

import_stmt       = "import" IDENTIFIER ";" ;

module_decl       = "module" IDENTIFIER ":" INDENT 
                       { top_level_stmt } 
                    DEDENT ;

// ── Statements ─────────────────────────────────────────

statement         = variable_decl
                  | assignment ";" 
                  | expression_stmt ";"
                  | return_stmt ";"
                  | if_stmt
                  | while_stmt
                  | for_stmt
                  | break_stmt ";"
                  | continue_stmt ";"
                  | expression_stmt                // newline-terminated
                  ;

variable_decl     = "var" IDENTIFIER [ ":" type ] [ "=" expression ] ;

assignment        = lvalue "=" expression ;
lvalue            = IDENTIFIER 
                  | postfix_expr "." IDENTIFIER 
                  | postfix_expr "[" expression "]" 
                  ;

expression_stmt   = expression ;

return_stmt       = "return" [ expression ] ;

break_stmt        = "break" ;
continue_stmt     = "continue" ;

// ── Control Flow ───────────────────────────────────────

if_stmt           = "if" expression ":" block
                    { "elif" expression ":" block }
                    [ "else" ":" block ] ;

while_stmt        = "while" expression ":" block ;

for_stmt          = "for" IDENTIFIER "in" expression ":" block ;

block             = INDENT statement { statement } DEDENT ;

// ── Function Definition ────────────────────────────────

function_def      = "func" IDENTIFIER "(" [ parameters ] ")" 
                    [ "->" type ] ":" block ;
parameters        = parameter { "," parameter } ;
parameter         = IDENTIFIER ":" type ;

// ── Types ──────────────────────────────────────────────

type              = "int" 
                  | "float" 
                  | "bool" 
                  | "string" 
                  | IDENTIFIER              // module type (Servo, Arduino, etc.)
                  | type "[" [ INTEGER ] "]"  // array type
                  ;

// ── Expressions ────────────────────────────────────────

expression        = or_expr ;

or_expr           = and_expr { "or" and_expr } ;
and_expr          = not_expr { "and" not_expr } ;
not_expr          = [ "not" ] comparison ;

comparison        = additive { ( "==" | "!=" | "<" | ">" | "<=" | ">=" ) additive } ;
additive          = multiplicative { ( "+" | "-" ) multiplicative } ;
multiplicative    = unary { ( "*" | "/" | "%" ) unary } ;
unary             = [ "-" | "!" ] postfix_expr ;

postfix_expr      = primary { call_suffix | dot_suffix | index_suffix } ;
call_suffix       = "(" [ arguments ] ")" ;
dot_suffix        = "." IDENTIFIER ;
index_suffix      = "[" expression "]" ;

primary           = INTEGER
                  | FLOAT
                  | STRING
                  | "true"
                  | "false"
                  | "null"
                  | IDENTIFIER
                  | array_literal
                  | "(" expression ")"
                  ;

arguments         = expression { "," expression } ;

array_literal     = "[" [ expression { "," expression } ] "]" ;

// ── Lexical Tokens (non-terminals from lexer) ──────────

IDENTIFIER        = LETTER { LETTER | DIGIT | "_" } ;
INTEGER           = DIGIT { DIGIT } ;
FLOAT             = DIGIT { DIGIT } "." DIGIT { DIGIT } ;
STRING            = '"' { CHAR } '"' ;
                  // CHAR = any character except " or \, 
                  //        or escape sequences: \", \\, \n, \t
INDENT            = increase in leading whitespace depth ;
DEDENT            = decrease in leading whitespace depth ;
NEWLINE           = end of line terminator ;
```

## 5. Hardware `Init()` Object Pattern — Semantics

### 5.1 Design

Every hardware module is a **compiler-known built-in** with the following contract:

1. **Namespace**: Module names are PascalCase global identifiers (`Arduino`, `Servo`, `LED`, `Motor`, `Sensor`).
2. **Initialization**: Each module exposes a static method `Init(...)` that takes hardware-specific arguments and returns an **opaque handle** of the module's nominal type.
3. **Handle**: The return value is a compile-time-allocated resource handle. It behaves like a value type (copy semantics are shallow — copying a handle references the same underlying hardware resource).
4. **Methods**: After initialization, the handle supports method calls via dot notation (e.g., `myServo.write(90)`).
5. **Compile-time validation**: The compiler validates that module names are known, pin numbers are within valid ranges, and method names exist on the module type. Unknown modules, invalid pins, and undefined methods are compile errors.

### 5.2 Built-in Modules (v1)

#### `Arduino`
```
Arduino.Init() -> Arduino
```
- Initializes the Arduino runtime: sets up `init()`, configures pin modes, starts `Serial` if needed.
- Returns an `Arduino` handle. In v1 this handle has no methods (it's a sentinel ensuring `Init()` was called).
- Calling `Arduino.Init()` more than once is valid (idempotent) — subsequent calls return the same handle.
- **C translation**: Generates `init();` call in `setup()`.

#### `Servo`
```
Servo.Init(pin int) -> Servo
```
- `pin`: The digital pin number to which the servo signal wire is connected.
- Returns a `Servo` handle bound to that pin.
- Valid pin range: 0–13 (AVR digital pins). Pins outside this range are a compile error.

**Methods on Servo handle**:
| Method | Signature | Description |
|--------|-----------|-------------|
| `write` | `write(angle int)` | Sets servo angle. Range: 0–180. |
| `read` | `read() -> int` | Reads current angle. |
| `attached` | `attached() -> bool` | Returns whether servo is attached. |
| `detach` | `detach()` | Detaches the servo from the pin. |

- **C translation**: Maps to `<Servo.h>` Arduino library. Each `Servo.Init(pin)` generates a `Servo` C++ object instance, calls `.attach(pin)`, and returns an index/handle into a compiler-maintained registry.

#### `DigitalPin` (built-in for GPIO)
```
DigitalPin.Init(pin int, mode int) -> DigitalPin
```
- `pin`: Digital pin number (0–13).
- `mode`: `0` for INPUT, `1` for OUTPUT, `2` for INPUT_PULLUP. Constants `DigitalPin.INPUT`, `DigitalPin.OUTPUT`, `DigitalPin.INPUT_PULLUP` are available.

**Methods on DigitalPin handle**:
| Method | Signature | Description |
|--------|-----------|-------------|
| `write` | `write(value int)` | Sets pin HIGH (non-zero) or LOW (0). |
| `read` | `read() -> int` | Reads pin state. Returns 0 or 1. |

#### `AnalogPin` (built-in for analog I/O)
```
AnalogPin.Init(pin int) -> AnalogPin
```
- `pin`: Analog pin number (A0–A5, specified as 0–5).

**Methods on AnalogPin handle**:
| Method | Signature | Description |
|--------|-----------|-------------|
| `read` | `read() -> int` | Reads 10-bit analog value (0–1023). |
| `write` | `write(value int)` | Writes PWM value (0–255) to analog pin. |

#### `Serial` (built-in UART singleton)

`Serial` is a **static singleton module** used directly on the module name — it
has no `Init()` and produces no handle/storage:

```
Serial.begin(9600)          // must be called before any other Serial method
Serial.println("ready")
Serial.print(42)            // accepts int, float, string, or bool
Serial.write(ch)            // raw byte write
```

**Methods**:
| Method | Signature | Description | C mapping |
|--------|-----------|-------------|-----------|
| `begin` | `begin(baud int)` | Start UART at baud rate | `Serial.begin(baud)` |
| `print` | `print(value)` | Write text/number (int, float, string, bool) | `Serial.print(value)` |
| `println` | `println(value)` | Like `print` with a trailing newline | `Serial.println(value)` |
| `write` | `write(byte int)` | Write a single raw byte | `Serial.write(byte)` |
| `available` | `available() -> int` | Bytes waiting in the RX buffer | `Serial.available()` |
| `read` | `read() -> int` | Read one byte, or -1 if none | `Serial.read()` |

`Serial.begin(...)` and other bare top-level `Serial` calls are emitted in
`setup()`. The host-side viewer is `python voltc.py monitor -p COM3`.

### 5.3 Extensibility

Adding a new hardware module in v2+ requires:
1. Register the module name and its `Init()` signature in the compiler's built-in registry.
2. Define the mapping from module methods to C library calls.
3. Optionally provide a `.volt` declaration file for IDE autocompletion.

No changes to the grammar, parser, or language semantics are needed — the `Module.Init(args)` pattern is universal.

### 5.4 Compile-time Allocation Model

Since Volt targets microcontrollers with no heap (or limited heap), hardware handles are **statically allocated**:

```
var s1 = Servo.Init(5)
var s2 = Servo.Init(6)
```

Compiles to C conceptually as:
```c
Servo __volt_servo_0;
Servo __volt_servo_1;
// in setup():
__volt_servo_0.attach(5);
__volt_servo_1.attach(6);
```

The compiler assigns unique C identifiers to each `Init()` call site. There is no dynamic allocation.

## 6. Program Structure & Entry Point

A `.volt` file compiles to a complete Arduino sketch:

```volt
// Blink example
var led = DigitalPin.Init(13, DigitalPin.OUTPUT)
var board = Arduino.Init()

while true:
    led.write(1)
    Delay(1000)          // built-in: delays for N milliseconds
    led.write(0)
    Delay(1000)
```

The compiler generates:
- C `#include` directives for required Arduino libraries
- Global variable declarations for hardware handles
- `setup()` function containing `Arduino.Init()` and all `Module.Init()` calls
- `loop()` function containing the main program body

### 6.1 Built-in Functions (always available, no import required)

| Function | Signature | Description | C mapping |
|----------|-----------|-------------|-----------|
| `Delay` | `Delay(ms int)` | Block for `ms` milliseconds | `delay(ms)` |
| `DelayMicroseconds` | `DelayMicroseconds(us int)` | Block for `us` microseconds | `delayMicroseconds(us)` |
| `Millis` | `Millis() -> int` | Returns ms since boot | `millis()` |
| `Micros` | `Micros() -> int` | Returns us since boot | `micros()` |

## 7. Scope & Name Resolution

Volt uses **lexical scoping**:

- **Global scope**: Top-level statements, function definitions, and module declarations.
- **Function scope**: Parameters and variables declared with `var` inside a function body.
- **Block scope**: Variables declared inside `if`/`elif`/`else`/`while`/`for` blocks are scoped to that block.
- **Shadowing**: Declaring a variable with the same name in an inner scope shadows the outer declaration (warning emitted).

### 7.1 Function Call Semantics

- **Pass by value**: All primitive types are passed by value.
- **Module handles**: Passed by value (shallow copy — both refer to the same hardware).
- **Arrays**: Passed by reference (pointer to first element in generated C).
- **No closures**: Functions cannot capture variables from enclosing scopes (this is a v1 limitation for embedded simplicity). No nested function definitions.

## 8. Operator Precedence Table

| Precedence | Operators | Associativity |
|-----------|-----------|---------------|
| 1 (highest) | `.` (member), `()` (call), `[]` (index) | Left |
| 2 | `-` (unary negate), `!` (logical not) | Right |
| 3 | `*`, `/`, `%` | Left |
| 4 | `+`, `-` (binary) | Left |
| 5 | `<`, `>`, `<=`, `>=` | Left |
| 6 | `==`, `!=` | Left |
| 7 | `not` | Right |
| 8 | `and` | Left |
| 9 | `or` | Left |
| 10 (lowest) | `=` (assignment) | Right |

## 9. Error Handling Policy (v1)

- **Compile errors**: Type mismatches, unknown identifiers, invalid pin ranges, syntax errors — all produce clear error messages with line numbers and halt compilation. No silent fallbacks.
- **Runtime errors**: Minimal. Since v1 targets microcontrollers, there is no exception mechanism. Out-of-bounds array access is **undefined behavior** (responsibility of the programmer, matching C semantics). Invalid pin operations at runtime (e.g., writing to an unattached servo) may cause AVR-level undefined behavior.
- **Warnings**: Emitted for unused variables, shadowed declarations, unreachable code. Warnings do not halt compilation.

## 10. Sample Volt Program

```volt
// servo_sweep.volt — Sweep a servo back and forth
import Servo

var board = Arduino.Init()
var myServo = Servo.Init(9)
var pos int = 0

func sweep(start int, end int, step int):
    var angle = start
    while angle <= end:
        myServo.write(angle)
        Delay(15)
        angle = angle + step

while true:
    sweep(0, 180, 1)
    sweep(180, 0, -1)
```

## Appendix A: Reserved IDENTIFIER Convention

Identifiers beginning with `__volt_` or `__builtin_` are reserved for compiler-generated symbols and must not be used in user code. Violation is a compile error.

## Appendix B: BNF Notation Key

| Notation | Meaning |
|----------|---------|
| `"keyword"` | Literal terminal |
| `IDENTIFIER` | Lexer token (non-terminal) |
| `[ X ]` | Zero or one of X |
| `{ X }` | Zero or more of X |
| `X | Y` | X or Y (alternation) |
| `( X )` | Grouping |
